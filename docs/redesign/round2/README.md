## Cost on the real site (static export, per-route JS budget of about 152 KB gz + 1 KB slack, readable without JS)

- **mission-control.** One island of roughly 3 to 4 KB gz on `/` (receipts, sources mode, refresh, filters). Figures render at build from the same data as today, and the island re-reads `/status.json` same-origin. The commit feed needs a source that is fresher than a deploy: extend the box's status.json timer to write the last commits, or accept build-time staleness. No JS: the full dashboard renders, figures are plain links to their sources, rows are `<details>`, filters disappear. Numbers swap in place in tabular figures, so CLS stays under 0.01.
- **blocks.** The costliest: about 6 to 8 KB gz on each of `/`, `/shop/`, `/partner/` (drag, resize, FLIP, tray, share). A saved layout applied after paint moves the page, which would break the 0.01 CLS gate at 375 px; it needs a tiny inline script in `<head>` that applies the saved order before paint, and so a CSP hash in the Caddyfile. Mobile is one column, arrangement only. No JS: the default arrangement as a plain CSS grid, dock hidden; container queries need no JS.
- **product-studio.** About 4 to 5 KB gz on `/` and `/shop/` for the console and five demos. No JS: the console shows the recorded result for this site, the API and Action panels stack as plain sections, each demo shows its first state. ADR 0001 says the Site never hosts a Product, so the real page must not run checks: the input links out to `check.hrabovskyi.online` once it exists, and until then only the recorded result ships. The simulation is for this prototype only.

## The system and what it encodes (correct me)

Tokens in `shared/tokens.css`: six constants (grid 4, target 44, curve, stroke 1.75, type 15, one soft shadow and no lit edges), OKLCH 12-step neutral and accent ramps with Radix roles, dark and light as the same names, contrast ratios written beside them (all text pairs pass 4.5:1). Controls have a quiet weight: a 1 px hairline on a surface one step off the page, one soft drop, medium-weight text, 8 px radius, 44 px targets. Hover lifts the border one step, press sinks the fill one step and moves 1 px, focus is the 2 px accent ring; primary is the same shape with a restrained accent tint (never a solid slab), ghost has no border until hover, a pressed toggle sits recessed, and the segmented control is a recessed track with the chosen segment as a raised hairline tile. Type uses the faces the live site ships: Inter (variable, in `shared/fonts/` under the OFL) at 400/500/600 for everything, Bricolage Grotesque for page titles only (36 to 52 px, never below about 26 px), and the system monospace only where it carries meaning: figures, paths, hashes, code. Sizes 12/13/15/17/20/28 px with line-heights 16/20/24/28/28/32 on the 4 px grid; labels and meta are sans, sentence case. Icons are Lucide at one stroke. The **knobs** button in the top bar tunes theme, density, accent and motion live and shows the derivation. Values encoded: a number without a source is not shown; zero is printed, not hidden; what is illustrative says so; nothing nags to buy; the free part of each tool is listed before the paid part.

Tuning pass on mission-control (calmer controls, type, spacing; no location shown; WebMCP row names `document.modelContext`): its screenshots are re-taken; blocks and product-studio share the tokens, so their pages were regenerated and re-checked, but their screenshots and every `demo.gif` show the pre-tuning controls. Checked: axe-core on every page at 1440 light, 1440 dark and 390 light: 0 violations. 0 console errors. No horizontal scroll at 390. Not done: the ~12-tile style board from the ui-design skill. These three directions come from the brief, so this round tests structure and behaviour more than surface.
